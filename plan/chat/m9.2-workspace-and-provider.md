# M9.2 — Workspace shell and provider foundation

Parent: [`../interactive_chat_plan.md`](../interactive_chat_plan.md) §5, §6, §7, §14, §15

Effort: 4 days

## Scope

Everything needed to connect to a provider, pick a model, send a message and stream an answer — **with no grounding, no context, no citations, no history**. Those are M9.3.

The exit state is deliberately an ungrounded chatbot, which is exactly what the plan says not to ship. It therefore sits behind a build flag that stays off in production until M9.3 exits. Do not skip §7 of this document.

## Do not do these

- **Do not extract a shared `SideWorkspace` component.** `SearchDrawer`'s focus trap carries a special case for its nested mobile filter sheet (`SearchDrawer.tsx:72`) that only it needs. Copy the drawer mechanics into `ChatDrawer`. Extraction happens in M9.5, once two real consumers show what is genuinely common. M7.5 accessibility is explicitly at risk here.
- **Do not add `"chat"` to `PaneSourceType`** in `state/store.ts:5`. Reader panes stay dedicated to canonical content and notes.
- **Do not add a provider SDK.** The OpenAI and Anthropic JS SDKs send `x-stainless-*` headers that break the CORS preflight on at least one target endpoint, and they are large. Raw `fetch` + a hand-written SSE parser.
- **Do not build OAuth.** Deferred to M9.6 (`../interactive_chat_plan.md` §5.5).
- **Do not persist the API key anywhere but `sessionStorage`.**

## 1. Provider registry — `apps/web/src/chat/providers.ts`

Pure data plus one lookup. No network code.

```ts
export interface ProviderConfig {
  id: ProviderId;
  labelKey: string;             // i18n key, not a literal
  baseUrl: string;              // no trailing slash
  modelsPath: string;           // e.g. "/models"
  modelsNeedAuth: boolean;      // OpenRouter: false (usable before connecting)
  validatePath: string;         // §1a — NOT always modelsPath. Always authenticated.
  extraHeaders: Record<string, string>;
  cspOrigin: string;
  keyHelpUrl: string;
  privacyNoteKey: string;       // i18n key describing this provider's retention posture
  supportsPrivacyRouting: boolean;  // only OpenRouter
  satisfiesNoTraining: "byRouting" | "byUserAssertion" | "never";  // §1b — licence gate
  usageOptIn: "openrouter" | "streamOptions";   // §4a — the two forms are NOT interchangeable
  // §4b — capability-driven, NOT a per-provider constant. `caps` comes from the
  // model catalogue; when it is unknown the body must be left alone.
  suppressReasoning(body: Record<string, unknown>, caps: ModelReasoningCaps | null): void;
}

export type ProviderId = "openrouter" | "anthropic" | "gemini";
```

**Two providers ship in M9.2.** Values confirmed by [`m9.0-findings.md`](m9.0-findings.md) on 2026-07-29:

| id | baseUrl | modelsPath | modelsNeedAuth | validatePath | extraHeaders | usageOptIn | cspOrigin |
|---|---|---|---|---|---|---|---|
| `openrouter` | `https://openrouter.ai/api/v1` | `/models` | `false` | **`/key`** | `HTTP-Referer`, `X-Title` | `openrouter` | `https://openrouter.ai` |
| `gemini` | `https://generativelanguage.googleapis.com/v1beta/openai` | `/models` | `true` | `/models` | *(none — keep minimal)* | `streamOptions` | `https://generativelanguage.googleapis.com` |

### 1a. `validatePath` is separate from `modelsPath` — and this is not a nicety

`../interactive_chat_plan.md` §6 says a pasted key is validated with one cheap authenticated call to "the provider's models endpoint". **For OpenRouter that cannot work**: `GET /api/v1/models` requires no authentication and returns HTTP 200 with the full catalogue no matter what the `Authorization` header contains — the same property that makes the pre-connect picker possible (`m9.0-findings.md` §1, §11). Validating through it accepts any string, including an empty one, and the user discovers their key is wrong when their first question dies mid-stream.

Use `GET https://openrouter.ai/api/v1/key` with `Authorization: Bearer <key>`. It is documented for exactly this. Two fields from its response feed UI the plan already wants:

- `limit_remaining` → the credit display in `../interactive_chat_plan.md` §7.2, from a real source rather than an estimate.
- `is_free_tier` → which OpenRouter rate limit applies (50/day vs 1,000/day, §4 of the findings), so the rate-limit error can name the actual number.

**Blocking check before you write `validateKey()`:** the CORS behaviour of `GET /api/v1/key` was **not** tested in M9.0 — only `/models` and `/chat/completions` were. Verify it answers a browser preflight with `access-control-allow-origin` before building on it. If it does not, key validation needs a different design, not a different URL, and that is worth knowing on day one rather than day three.

`modelsNeedAuth: false` must never be read as "validation is free".

### 1b. `satisfiesNoTraining` — what the licence gate consults

M9.1 ships `ai_context_policy = allowed_no_training` for works whose licence permits AI use only under no-training terms. M9.3's gate needs to know whether the *currently connected provider and settings* satisfy that condition, and the answer differs in kind per provider:

| Provider | Value | Meaning |
|---|---|---|
| `openrouter` | `"byRouting"` | Satisfied when the privacy-routing toggle is on. Enforced by the provider: a non-compliant route returns HTTP 404 rather than downgrading silently (findings §3) |
| `gemini` | `"byUserAssertion"` | Google's free tier trains on submitted content; its paid tier does not, and **the app cannot tell which tier a key is on** (findings §10a). Satisfied only if the user explicitly asserts a paid key in settings. Defaults to unsatisfied |

`"never"` exists for a future provider with no no-training path at all. A provider that cannot satisfy the condition must make `allowed_no_training` sources appear disabled with a reason, exactly like `prohibited` ones.

`ProviderId` is therefore `"openrouter" | "gemini"` for now.

Two providers are deliberately absent, both already investigated — **do not re-add either without reading why**:

- **`api.openai.com`** — its completions response omits `Access-Control-Allow-Origin` even though the preflight passes. A curl test will tell you it works; a browser will not. OpenAI models are reachable through OpenRouter.
- **`api.anthropic.com`** — technically reachable (M9.0 §1a), but a direct adapter needs an Anthropic API key, and a Claude Pro subscription is not one: consumer plans and API access are separate billing pools. OpenRouter carries 26 Claude models at the same published rates, including `anthropic/claude-haiku-4.5` at $1/$5 per million. See the parent plan §5.4a.

Model-picker fields from the OpenRouter catalogue: `id`, `name`, `context_length`, `pricing.prompt`, `pricing.completion`, and `"tools" in supported_parameters`.

A unit test asserts every `cspOrigin` in the registry appears in the deployed CSP string. That test is what stops a provider being added without its origin.

## 3. SSE parser — `apps/web/src/chat/sse.ts`

The single most bug-prone piece. Write it standalone and test it hard before wiring it up.

```ts
export async function* parseSse(
  body: ReadableStream<Uint8Array>,
  signal: AbortSignal,
): AsyncGenerator<SseEvent>;
```

Must handle:

- Events split across chunk boundaries **mid-line and mid-UTF-8-sequence** (use a single `TextDecoder` with `{ stream: true }`; do not decode per chunk).
- `data:` lines with and without a leading space.
- Comment lines starting with `:` (keep-alive) — ignored.
- Multi-line `data:` accumulation within one event.
- `data: [DONE]` terminator.
- Malformed JSON in one event → skip that event, keep the stream alive; do not abort the answer over one bad frame.
- `signal.abort()` → cancel the reader, resolve cleanly, no unhandled rejection. **Verified working** on OpenRouter and Gemini in M9.0.
- A stream that ends without `[DONE]` → treated as truncated, not as success.
- **Discard `delta.reasoning` and `delta.reasoning_details`** (§4b). Real streams carry them; the plan forbids storing chain-of-thought.

Tests feed a mock `ReadableStream` with deliberately hostile chunking: one byte at a time, a chunk boundary inside a multi-byte Cyrillic character, an event split across three chunks.

## 4. Adapter — `apps/web/src/chat/client.ts`

One implementation for all providers; differences come from the registry.

```ts
export interface ChatRequest {
  providerId: ProviderId;
  model: string;
  messages: ChatMessage[];
  maxTokens: number;
  privacyRouting: boolean;     // adds provider.zdr / data_collection when supported
  signal: AbortSignal;
}

export interface ChatStreamHandlers {
  onDelta(text: string): void;
  onMeta(meta: Partial<ChatRunMeta>): void;   // actual model, as soon as known
}

export interface ChatRunMeta {
  providerId: ProviderId;
  requestedModel: string;
  actualModel: string | null;   // routers may substitute; show what actually answered
  finishReason: string | null;
  usage: {
    promptTokens?: number;
    completionTokens?: number;
    // REQUIRED for any cost or budget display. Gemini reported prompt 20 +
    // completion 4 with total 136 — hidden thinking tokens appear ONLY here,
    // so prompt+completion under-reports by an order of magnitude (§4a).
    totalTokens?: number;
    cost?: number;
  } | null;
  retries: number;
  incomplete: boolean;
}

export async function streamChat(req, handlers): Promise<ChatRunMeta>;
export async function listModels(id: ProviderId, signal?: AbortSignal): Promise<ChatModel[]>;
// Hits provider.validatePath, which is authenticated by construction (§1a).
export async function validateKey(id: ProviderId, key: string): Promise<void>;
```

### 4a. Usage opt-in is provider-specific — measured, not assumed

Without it, the streamed response carries no usage at all and the cost display has nothing to read. The two forms are **not** interchangeable ([`m9.0-findings.md`](m9.0-findings.md) §9):

| `usageOptIn` | Body field | Providers |
|---|---|---|
| `"openrouter"` | `usage: { include: true }` | OpenRouter |
| `"streamOptions"` | `stream_options: { include_usage: true }` | Gemini — sending `usage` returns **HTTP 400 `Unknown name "usage"`** |

`usage: {include: true}` is an OpenRouter extension, not standard OpenAI. Anthropic's form is unverified; test before its adapter ships.

**Use `total_tokens` for any cost display, not `prompt + completion`.** Gemini reported `prompt 20 + completion 4` with `total 136` — hidden thinking tokens appear only in the total, so adding the parts under-reports by an order of magnitude.

### 4b. Reasoning suppression is mandatory, not an optimisation

M9.0 found that `openrouter/free` with `max_tokens: 160` streamed 160 chunks and produced **an empty answer**: the whole budget went to hidden reasoning (`reasoning_tokens: 188`, `finish_reason: "length"`, `content: ""`). Gemini 2.5 Flash does the same with its thinking budget. Shipped without this, a user's first question streams for fourteen seconds and shows nothing.

| Provider | What to send | Notes |
|---|---|---|
| OpenRouter | `reasoning: { enabled: false }` | Verified: `reasoning_tokens: 0`, `finish_reason: "stop"`, full content |
| OpenRouter | ~~`reasoning: { exclude: true }`~~ | **Does not work.** Only hides the output; the budget is still consumed and content still comes back empty |
| Gemini **2.5 Flash / Flash-Lite** | `reasoning_effort: "none"` | Google documents this for 2.5 models |
| Gemini **2.5 Pro**, **Gemini 3.x** | *nothing — do not send a disable flag* | Google: *"Reasoning cannot be turned off for Gemini 2.5 Pro or 3 models."* `extra_body.thinking_config` offers `thinking_level` and `include_thoughts` but no "off" |

**This is why `suppressReasoning` takes a capability argument.** Reasoning suppression is a property of the *model*, not the provider, and a per-provider function will send a flag that mandatory-reasoning models reject:

```ts
export interface ModelReasoningCaps {
  mandatory: boolean;             // OpenRouter: "do not send effort:'none' — the model rejects it"
  supportedEfforts?: string[];
  supportsMaxTokens?: boolean;
}
```

- **OpenRouter** exposes this per model on `GET /api/v1/models` under a `reasoning` object (`mandatory`, `supported_efforts`, `default_effort`, `default_enabled`, `supports_max_tokens`). Read it in `listModels()` and carry it on `ChatModel`.
- **Gemini** has no such metadata; derive `mandatory` from the model id — 2.5 Flash / Flash-Lite are suppressible, everything else is not. Keep that mapping in one place with a comment pointing at the Google doc, because it will need editing when a model is added.
- **`caps === null` means unknown, and unknown must mean "send nothing".** Dynamic routers — `openrouter/free` included — omit the `reasoning` field entirely from their metadata, so the app cannot know in advance. This does not contradict the finding that `reasoning: {enabled: false}` worked on `openrouter/free`; it means the app cannot *prove* it will, and must survive the case where it does not.

**When suppression is unavailable, the fallback is budget**, not hope: raise `max_tokens` far enough above the expected answer that hidden reasoning cannot consume all of it, and keep the `emptyAnswer` error for when it still does. Never send a disable flag that will be rejected.

The SSE parser must also **discard** `delta.reasoning` and `delta.reasoning_details` — confirmed present in real streams. The plan forbids storing chain-of-thought (§12), so drop them explicitly rather than relying on them being ignored.

Treat `finish_reason: "length"` with empty content as its own typed error (`emptyAnswer`), not a blank message. With mandatory-reasoning models it is a *likely* path, not an edge case, so its message must suggest raising the answer cap or changing model.

### 4c. Resulting request body

```jsonc
{
  "model": "...",
  "messages": [...],
  "stream": true,
  "max_tokens": 1500,
  // exactly one of these two, per providerConfig.usageOptIn
  "usage": { "include": true },
  "stream_options": { "include_usage": true },
  // via providerConfig.suppressReasoning()
  "reasoning": { "enabled": false },
  // only when providerConfig.supportsPrivacyRouting && privacyRouting
  "provider": { "zdr": true, "data_collection": "deny" }
}
```

Retry policy: at most two retries, exponential backoff, honour `Retry-After`. **Never** retry 401, 402, 403, or a user abort.

## 5. Errors — `apps/web/src/chat/errors.ts`

```ts
export type ChatErrorKind =
  | "auth"            // 401/403 -> "check your key"
  | "credit"          // 402     -> "add credit at <provider>"
  | "rateLimit"       // 429     -> retryAfter seconds
  | "modelUnavailable"
  | "privacyConstraint"  // 404: no endpoint satisfies zdr/data_collection — COMMON, see below
  | "emptyAnswer"        // finish_reason "length" with no content (reasoning ate the budget)
  | "network"
  | "malformedStream"
  | "aborted";

export class ChatError extends Error {
  readonly kind: ChatErrorKind;
  readonly retryAfterSeconds?: number;
  // Never carries a provider response body, prompt, key, or source text.
}
```

Map HTTP status → kind in one place. Each kind gets an i18n key and a concrete next action.

`privacyConstraint` is not theoretical — M9.0 measured that **most individually named free OpenRouter models return HTTP 404** under `zdr + data_collection: deny` (`"No endpoints found matching your data policy"`), while `openrouter/free` succeeds because the router filters to compliant endpoints. Any user who picks a named free model from the catalogue will hit this. The message must name the cause and offer the two real options: switch model, or relax the privacy setting with a clear warning.

## 8. Settings UI — `apps/web/src/components/chat/ChatSettings.tsx`

- Provider select, populated from the registry.
- API key input: `type="password"`, `autoComplete="off"`, never pre-filled with the stored value — show a "Connected" state instead of echoing it back.
- A link to `keyHelpUrl` with guidance to **create a dedicated key with a spend limit**.
- Connect → `validateKey()` → store on success; show a typed error on failure. A bad key must fail here, not mid-answer.
- Disconnect → `clearKey()`, immediately.
- Model picker: `listModels()` with a text filter (OpenRouter lists hundreds). Show id, context length and price. For OpenRouter this loads before connecting (`modelsNeedAuth: false`) so a first-time user can browse.
- **Default model: none. Decided** ([`m9.0-findings.md`](m9.0-findings.md) §7a). The picker opens with no selection and the Assistant cannot send until the user chooses. `openrouter/free` passes ZDR + `data_collection: deny` but produced unusable Bulgarian in two of four samples, one of them a content-safety classifier that replied `"User"` — a default that returns gibberish half the time reads as a broken app, not as free-model variance. Do not preselect anything, and do not present free models as the recommended path. Revisit only against `m9.0b-bulgarian-benchmark.md`.
- Privacy routing toggle, shown only when `supportsPrivacyRouting`. Default on.
- **Gemini paid-tier assertion** — a checkbox, default **off**, shown only for `satisfiesNoTraining: "byUserAssertion"` providers (§1b): *"My Gemini key is on a paid tier."* While off, works marked `ai_context_policy = allowed_no_training` are excluded from context. The app cannot detect the tier, so this is an assertion, and the copy must say what it is being relied on for.
- Per-provider privacy note, including the sentence that the app cannot control or detect the user's own account-level prompt logging. **Draft English wording for both providers is in [`m9.0-findings.md`](m9.0-findings.md) §10c** — use it as the source text for the i18n keys rather than writing new copy. The Gemini note must carry Google's free-tier data-use terms plainly; that is the single most consequential sentence in the settings UI.

The Anthropic header's name will be visible to anyone reading the network tab. Say plainly in the UI that "dangerous" refers to a developer shipping their own key in client code, which is not what this is. (Moot in M9.2 — the Anthropic adapter is deferred — but keep the note for whenever it revives.)

The same honesty applies to Gemini: **Google's own guidance recommends against using API keys directly from client-side code** ([`m9.0-findings.md`](m9.0-findings.md) §10b). This app's posture is materially different from what that warning targets — the user's own key, in `sessionStorage`, for the tab's lifetime, never bundled and never sent to our server — but the divergence is real. State it rather than let a user discover it in Google's docs afterwards.
