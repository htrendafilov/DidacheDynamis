# M9.0 — Provider feasibility spike

Parent: [`../interactive_chat_plan.md`](../interactive_chat_plan.md) §15
Blocks: M9.2, M9.3
Effort: 1 day
Deliverable: **a written findings document**, `plan/chat/m9.0-findings.md`. Throwaway code only.

## Why this exists

Four questions decide the shape of M9.2 and M9.3, and all four have answers that no amount of reading can supply:

1. Which providers can a browser actually reach? (CORS)
2. Does the app's real CSP allow exactly those origins and nothing more?
3. Can OpenRouter satisfy `zdr: true` + `data_collection: "deny"` at all, and on free models?
4. How wrong is the token estimator on Bulgarian text?

Do not start M9.2 before this file exists and its decision tables are filled in.

## Rules

- **No code from this spike is merged.** Delete `apps/web/public/spike.html` before opening any PR.
- **Use a throwaway API key** with a hard spend limit on every provider. Revoke all of them when done.
- **No key goes in the spike file.** Paste it into an input at runtime.
- Do not use any provider SDK. Raw `fetch` only — this is partly what is being tested.

## Check 2 — per-provider reachability (3 h)

For each provider, in this order. Record the raw outcome, not an interpretation.

### 2a. OpenRouter

```js
// Model list — no auth required. Use it for the pre-connect picker in M9.2.
await fetch("https://openrouter.ai/api/v1/models");

// Streamed completion
await fetch("https://openrouter.ai/api/v1/chat/completions", {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${key}` },
  body: JSON.stringify({
    model: "<pick one>",
    messages: [{ role: "user", content: "Say hello in Bulgarian." }],
    stream: true,
    usage: { include: true },
    max_tokens: 200,
  }),
  signal: controller.signal,
});
```

Record: does `GET /models` work unauthenticated from the browser? Does the stream arrive as SSE? **Does the final chunk carry a `usage` object when `usage: {include: true}` is set?** Does `controller.abort()` mid-stream terminate cleanly without an unhandled rejection?

### 2b. Anthropic

Base URL `https://api.anthropic.com/v1`, OpenAI-compatibility layer.

```js
headers: {
  "Content-Type": "application/json",
  Authorization: `Bearer ${key}`,
  "anthropic-dangerous-direct-browser-access": "true",
}
```

Record, separately:

- Does `POST /v1/chat/completions` work **with** the browser header?
- Does it fail **without** it? (Confirms the header is the mechanism, not incidental.)
- **Does `GET /v1/models` work through the compat layer with `Authorization: Bearer`,** or does it demand native `x-api-key` + `anthropic-version`? → If it demands native headers, decide now: either send native headers for the models call only, or ship a small static model list for Anthropic labelled "not live".
- Does the streamed response carry usage, and under what key?

### 2c. Gemini

Base URL `https://generativelanguage.googleapis.com/v1beta/openai`.

This is the uncertain one. Community reports say it works from a browser only when the OpenAI SDK's `x-stainless-*` headers are absent. Send the **minimum possible** header set:

```js
headers: { "Content-Type": "application/json", Authorization: `Bearer ${key}` }
```

Record:

- Does the CORS **preflight** (`OPTIONS`) succeed? `Content-Type: application/json` is not CORS-safelisted, so a preflight always happens. Check the Network tab for the OPTIONS request specifically, not just the POST.
- Does `Authorization: Bearer` authenticate, or does it only accept `?key=` in the URL? **A key in a URL is disqualifying** — §4.2 forbids credentials in URLs, and URLs land in history and referrers. If Bearer does not work, Gemini is out.
- Does streaming work? Does `GET /v1beta/openai/models` work?

### 2d. OpenAI direct

One check, to close the question in the findings rather than leave it to memory:

```js
await fetch("https://api.openai.com/v1/models", { headers: { Authorization: `Bearer ${key}` } });
```

Expected: CORS failure, no `Access-Control-Allow-Origin`. Record the exact console error. OpenAI models remain reachable through OpenRouter.

## Check 3 — the privacy branch (1 h)

This decides M9.2's default model and is the single most consequential output of the spike.

```jsonc
{
  "model": "<candidate>",
  "messages": [ ... ],
  "provider": { "zdr": true, "data_collection": "deny" }
}
```

Test against, at minimum:

- `openrouter/free`
- two or three currently-listed `:free` models
- one cheap paid model (e.g. a small Claude or Gemini model routed through OpenRouter)

Record for each: does the request succeed, or does OpenRouter return "no endpoints found matching your data policy" (or equivalent)?

Also record from the OpenRouter dashboard: the current state of the account-level toggles "enable free endpoints that may train on inputs" and "enable free endpoints that may publish prompts". These override nothing the app requests, but they determine what a *user* experiences by default and must be described in the privacy notice.

**Fill in this table. It is the exit criterion — "we tested it" is not.**

| Finding | M9.2 default |
|---|---|
| ☐ A free model satisfies ZDR + `data_collection: deny` | Ship it as default, labelled best-effort and rate-limited |
| ☐ Only paid models satisfy both | Ship **no** default. Picker opens empty with an explanation; Assistant unusable until the user chooses |
| ☐ No model satisfies both | Ship no default **and** no relaxation path. Reopen the architecture decision — this invalidates the browser-BYOK privacy premise |

## Check 4 — rate limits and catalogue (30 min)

- Current OpenRouter free-tier limits (requests/minute, requests/day, and the credit threshold that raises them). The plan assumes ~20 rpm / 50 per day; confirm.
- Does `openrouter/free` still resolve?
- Does the `/models` payload expose everything the picker needs: id, display name, context length, pricing, and a capability flag for tool support? List the actual field names — M9.2 codes against them.

## Check 5 — calibrate the token estimator (1 h)

The estimator in `chat/tokens.ts` (M9.3) has no tokenizer and must not under-count, or the budget in §8.3 is decorative.

1. Assemble ~10 prompts spanning the real mix: English WEB passage text, Matthew Henry prose, an Easton's entry, a Strong's entry, a Bulgarian user question, a Bulgarian question plus English context.
2. Send each with `max_tokens: 1` and `usage: {include: true}`; read `usage.prompt_tokens`.
3. Compare against the starting heuristic:

```ts
const estimateTokens = (s: string) =>
  Math.ceil(((asciiCount(s) / 3.6) + (nonAsciiCount(s) / 1.8)) * 1.2);
```

4. Record the estimate ÷ actual ratio per sample. **Tune the constants so the estimate is never below actual** on any sample, and record the final values plus the worst-case overshoot.
