# M9.3b — Chat layout refit

Parent: [`../interactive_chat_plan.md`](../interactive_chat_plan.md) §7.2
Depends on: M9.2 (drawer, provider, settings), M9.3 (context picker, history, sources)
Effort: 2 days
Status: **shipped 2026-07-31.** This document is the retained implementation brief.

## Problem

The Assistant panel is a single vertical stack, and every block above the message list is
`flex: none`. `.chat-panel` and `.chat-messages` already have the right flex rules
(`app.css:247`, `app.css:333` — `flex: 1; min-height: 0; overflow-y: auto`), so the message
list *would* expand. It cannot, because its siblings consume the panel before it gets a
turn.

Measured against the reported screenshot, at a typical docked width, the stack above the
messages is roughly:

| Block | Source | Approx. height |
|---|---|---|
| Header | `ChatPanel.tsx` header | 40 px |
| Disclaimer (3 lines) | `chat.disclaimer` | 75 px |
| History controls (2 rows, wrapped) | `ChatPanel.tsx` `.chat-history-controls` | 80 px |
| Provider block: name, "Connected", **credit line**, Disconnect | `ChatSettings.tsx:179-193` | 150 px |
| Model filter + model `<select>` | `ChatSettings.tsx:195-225` | 80 px |
| Model terms link + no-default caveat | `ChatSettings.tsx:231-246` | 90 px |
| Two privacy checkboxes (wrapping to 4 lines) | `ChatSettings.tsx:249-269` | 110 px |
| Context picker | `ContextPicker.tsx` | 60 px+ |

That is ~685 px of chrome before a single message. On a 900 px-tall drawer the reader is
left with a message viewport smaller than one answer, which is what the screenshot shows:
the answer is clipped mid-sentence and the context picker overlaps it.

Nothing here is wrong individually. The layout is wrong: **settings that are configured once
per session occupy permanent vertical space competing with the content the panel exists to
show.**

### A spec violation to fix while we are here

`ChatSettings.tsx:181-188` renders a remaining-credit figure
(`chat.settings.creditRemaining`). §7.2 records the opposite decision, dated 2026-07-30:

> **No credit display.** … the workspace shows no remaining-credit figure — it invites
> balance anxiety the app cannot act on, and spend control already lives where it belongs.

The shipped code predates or missed that decision. Remove the credit line as part of this
refit (it is also 1–2 lines of the chrome budget above). `limit_remaining` stays available
in `KeyInfo`; only the display goes. The free/paid rate-limit sentence stays — it is not a
credit figure, and it tells the reader which request ceiling applies.

## Target layout

Three rules:

1. **The message list is the only element that grows, and the only scroll region** in the
   panel body.
2. **Per-session settings live in the composer**, reachable in one click, occupying one row
   when closed.
3. **Per-turn context sits directly above the composer**, collapsed to one line by default —
   it describes the next turn, so it belongs next to where that turn is typed.

### Mobile, fullscreen

Same vertical order. Differences:

- The context strip starts collapsed and stays collapsed across turns.
- The model popover renders as a bottom sheet (full width, `max-height: 80vh`), not an
  anchored card, because an anchored popover at 360 px wide has nowhere to go.
- The composer toolbar drops the answer-language label to its code only (`BG ▾`).

## Component changes

### New: `apps/web/src/components/chat/ModelPicker.tsx`

Owns only presentation and the popover's open/close state. Everything that outlives the
popover stays in `ChatPanel`.

```ts
export function ModelPicker(props: {
  connected: boolean;
  onConnected: () => void;
  onDisconnect: () => void;
  selectedModel: ChatModel | null;
  onSelectModel: (model: ChatModel | null) => void;
  privacyRouting: boolean;
  onPrivacyRoutingChange: (value: boolean) => void;
  loggingConfirmed: boolean;
  onLoggingConfirmedChange: (value: boolean) => void;

```

That is `ChatSettings`'s existing prop list unchanged. The cleanest implementation is to
**rename and restructure `ChatSettings.tsx` into `ModelPicker.tsx`**, keeping its logic
(`connect`, `disconnect`, `listModels` effect, `formatPrice`, `selectableModels`) and
replacing only the markup. Do not fork the file; there must be one connect path.

`initialLoggingConfirmed()` stays exported from wherever it lands — `ChatPanel` calls it
for `useState`'s initialiser.

The composer toolbar row: model chip, answer-language control, `⚙` menu, Send/Stop. Small
enough to live inside `ChatPanel.tsx` instead; split only if `ChatPanel` gets unwieldy.

## CSS (`apps/web/src/styles/app.css`)

- `.chat-panel` — unchanged, already correct.
- `.chat-messages` — unchanged, already correct.
- Add `flex: none` explicitly to every other direct child of `.chat-panel`. It is the
  default, but stating it prevents the next block from quietly competing again.
- `.chat-composer` becomes `flex-direction: column` with a `.chat-composer-toolbar` row.
- `.chat-composer` gets `position: relative` to anchor the popover.
- `.chat-model-popover` — `position: absolute; bottom: calc(100% + 0.4rem); left: 0;
  max-height: min(60vh, 420px); overflow-y: auto; z-index: 2;` plus a border, background
  (`var(--bg)`), and shadow. On mobile (`.chat-drawer.fullscreen` scope) switch to a fixed
  bottom sheet.
- `.chat-context-strip` — one-line summary; `max-height: 40vh; overflow-y: auto` when
  expanded, so a pane-heavy workspace cannot push the composer off screen.

Delete the `.chat-settings-*` rules that no longer have markup (`app.css:273-331`), but
keep `.chat-settings-error` if the popover reuses the class.

## Accessibility — non-negotiable

1. **Render the popover in-tree, not through a portal.** `ChatDrawer`'s focus trap collects
   focusables via `drawer.querySelectorAll(...)` (`ChatDrawer.tsx:64-68`). A portal to
   `document.body` puts the popover outside the trap, and on mobile the drawer is
   `aria-modal` — the trap would then skip exactly the dialog the user is in.
2. **Escape inside the popover must close only the popover.** `ChatDrawer` registers
   Escape on `window` (`ChatDrawer.tsx:86-95`), so an unhandled Escape closes the entire
   workspace and loses the composer draft. The popover's `onKeyDown` must call
   `event.stopPropagation()` before closing itself. **Add a regression test for this** — it
   is the single most likely thing to break.
3. Chip: `<button aria-haspopup="dialog" aria-expanded={open} aria-controls={popoverId}>`.
   Popover: `role="dialog"` with an `aria-label`.
4. Model list: `role="listbox"`, options `role="option"` with `aria-selected`. Up/Down move
   the active option, Enter selects, the search box keeps focus (`aria-activedescendant`).
5. Focus moves to the search box on open and **returns to the chip on close**.
6. Click outside closes. Do not close on scroll.
7. The `⚙` menu is a `role="menu"` with `role="menuitem"` children, same Escape rule.
8. `.chat-messages` keeps `aria-live="polite"` and its `aria-label`.
9. The collapsed disclaimer's toggle needs an accessible name; the full text must remain
   reachable, never `display: none` without a control.

## Invariants that must not regress

Each of these is asserted by an existing test or recorded as a decision. Read them before
touching the connect path.

- The API key never reaches rendered output. `ChatPanel.test.tsx` asserts
  `document.body.innerHTML` does not contain the sentinel key after connecting. A popover
  that keeps the pasted value mounted after connect would fail this — `connect()` already
  clears `pastedKey`; keep that.
- Connect stays disabled until the terms acknowledgement **and** a non-empty key.
- **No model is preselected** (`m9.0-findings.md` §7a). The chip must read "Изберете модел"
  when `selectedModel === null`, and Send stays disabled.
- Filtering must not drop the selected model. Keep `selectableModels`
  (`ChatSettings.tsx:118-121`) — the filter narrows what can be *newly* picked only.
- `privacyRouting` and `loggingConfirmed` state stays in `ChatPanel` and continues to flow
  to **both** `ModelPicker` and `ContextPicker`. Toggling either must still re-run
  `ContextPicker`'s emission effect and drop `allowed_no_training` chips (§11). Moving this
  state into the popover would break the licence gate silently.
- `setLoggingConfirmed` still writes to sessionStorage on toggle.
- Disconnect still aborts the in-flight stream, clears the key, and clears the logging
  confirmation.
- Clear thread / Clear all stay disabled while `streaming`.
- The disclaimer stays present and unshortened in both languages
  (`chatTranslations.test.ts` asserts equal sentence counts).

## Tests

### Will break, and must be updated

- `ChatPanel.test.tsx` — **25 tests**. Nearly all route through `connectAndSelectModel()`,
  which uses `getByLabelText("OpenRouter API key")`, `getByRole("checkbox", {name:/eligible
  OpenRouter account/i})`, `getByRole("button", {name:"Connect"})` and
  `getByLabelText("Model")`. Fix the helper to open the popover first; most individual
  tests should then pass untouched. Do that before changing anything else — it is the
  cheapest signal that the refit preserved behaviour.
- `ChatPanel.injectionCorpus.test.tsx` — **8 tests**, same helper pattern.
- `ChatDrawer.test.tsx` — **8 tests**. The focus-trap test enumerates focusables; the count
  changes.
- `ContextPicker.test.tsx` — **18 tests**. Chips inside a closed `<details>` are still in
  the DOM, but verify `getByRole` behaviour in jsdom before assuming; if roles are hidden,
  have the tests expand the strip first rather than weakening the queries.

### New

- Escape inside the model popover closes the popover and **leaves the workspace open**.
- Focus returns to the model chip when the popover closes.
- No remaining-credit figure is rendered anywhere after connecting (§7.2 guard).
- The composer toolbar renders the selected model's name, and "select a model" when none.
- Structural: `.chat-messages` is the last flexible child, and the settings markup is not
  in the DOM while the popover is closed.

`scripts/check.sh` must pass — the canonical entrypoint, run before every PR.

## Definition of done

- [ ] Chrome above the message list is one header + one disclaimer line + (optional) the
      history notice. Nothing else.
- [ ] The message list is the only scroll region in the panel body, at both docked and
      full-screen sizes.
- [ ] All provider/model/privacy controls reachable in one click from the composer, with
      no control lost relative to today's panel.
- [ ] Context sits directly above the composer, collapsed by default, and its summary line
      states what the next turn will carry.
- [ ] No remaining-credit figure anywhere (§7.2).
- [ ] Every invariant in §"Invariants that must not regress" still asserted by a test.
- [ ] Escape in the popover does not close the workspace.
- [ ] `scripts/check.sh` passes; i18n key parity holds.

## Out of scope

Named so they are not silently smuggled in, and so the toolbar is not redesigned when they
land. §7.2 lists all three as expected eventually; none is required by this refit.

- **Answer-language control.** §7.2 asks for "follow UI language / English / Bulgarian".
  Today `ChatPanel` derives it from `uiLang` with no control. Leave a toolbar slot; wiring
  it is a separate change.
- **Thread selector and New chat.** §7.2 asks for both; `history.ts` supports multiple
  threads but the UI only ever restores the most recent one and offers no way to start a
  second without clearing the first. Belongs in the header or the ⚙ menu.
- **Retry and Copy answer** (§7.2), per-message actions on the assistant bubble.
- Any change to retrieval, budgeting, prompt assembly, citations, or history storage. This
  is a layout refit; `chat/*.ts` should not need to change at all.
